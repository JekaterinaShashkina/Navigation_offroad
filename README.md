# Навигатор для поездок по бездорожью

Мультиплатформенное навигационное приложение для бездорожья, созданное с использованием **Flutter** и **React (Vite)**.


## 09.11.2025 Рефакторинг приложения. Переход на Clean Architecture (Flutter)

Цель: отделить UI от бизнес‑логики, повысить читаемость, тестируемость и масштабируемость.

### Принципы

Зависимости направлены внутрь: UI → Presentation → Domain ← Data.

Domain ничего не знает о Flutter/Firebase/HTTP.

Data реализует контракты Domain (репозитории), общаясь с внешним миром (Firestore, локальное хранилище).

Presentation оркестрирует UseCase‑ы, подготавливает состояние для UI.

### 🔒 Firestore Rules (Правила доступа к данным)

```js
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    match /users/{userId} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && request.auth.uid == userId;
    }

    match /friend_requests/{requestId} {
      allow create: if request.auth != null &&
        request.resource.data.from_user_id == request.auth.uid;

      allow update: if request.auth != null &&
        resource.data.to_user_id == request.auth.uid;

      allow read: if request.auth != null &&
        (resource.data.from_user_id == request.auth.uid ||
         resource.data.to_user_id == request.auth.uid);
         
      allow delete: if request.auth != null &&
        (resource.data.from_user_id == request.auth.uid ||
         resource.data.to_user_id == request.auth.uid);
    }

    match /friends/{friendDoc} {
      allow create: if request.auth != null &&
        (request.resource.data.user_id == request.auth.uid ||
         request.resource.data.friend_id == request.auth.uid);

      allow read, delete: if request.auth != null &&
        (resource.data.user_id == request.auth.uid ||
         resource.data.friend_id == request.auth.uid);
    }
    
    match /routes/{routeId} {
      allow create: if request.auth != null && request.auth.uid == request.resource.data.userId;

      allow read: if request.auth != null && 
        (request.auth.uid == resource.data.userId || resource.data.isPrivate == false);

      allow update, delete: if request.auth != null && request.auth.uid == resource.data.userId;
    }
  }
}
```

Эти правила обеспечивают доступ к данным только их владельцам и предотвращают несанкционированные действия.

## Функциональность Flutter-приложения

### 🔐 Авторизация через Firebase
- Используется единая система авторизации с веб-приложением.
- Пользователь, зарегистрировавшийся в веб-версии, может войти в мобильное приложение с теми же учетными данными.

### 🏠 Главная страница
- После входа пользователь переходит на главную страницу с картой (режим *hybrid*) и навигационным меню снизу.
- При повторном входе авторизованные пользователи автоматически попадают на главную, без необходимости логиниться заново.

### 📱 Навигационное меню
- 🏠 **Home** — переход на главную страницу.
- 🗺️ **Routes** — список маршрутов, сохранённых и созданных через веб-приложение (единая база данных).
- 👥 **Friends** — функция добавления друзей.
- 👤 **Profile** — отображение информации о текущем пользователе и кнопка выхода из аккаунта.

### 🚗 Работа с маршрутами
- В разделе **Routes** можно выбрать маршрут и отобразить его на карте (режим *hybrid*). При нажатии на маршрут открывается детальная страница с его описанием, где под ним отображается кнопка **"Начать маршрут"** (Live Tracking) и **"Симуляция маршрута"** (симуляция передвижения по маршруту).
- В списке маршрутов:
  - Отображаются все маршруты, созданные пользователем.
  - Для каждого маршрута можно изменить статус **Private/Public**.
  - Добавлена кнопка с иконкой корзины для удаления маршрута.
    - Перед удалением отображается окно подтверждения (*"Are you sure you want to delete this route?"*).
    - Удаление маршрута необратимо.

### 🧭 Движение по маршруту (Live Tracking)
* При запуске маршрута приложение:
  * Определяет текущее местоположение пользователя через **Location API**.
  * Проверяет расстояние до точки старта маршрута:
    * Если пользователь находится ближе 30 метров — отслеживание маршрута начинается.
    * Если дальше — выводится уведомление с расстоянием до старта.
  * Ориентирует камеру Google Maps в направлении движения (с наклоном 60° и сдвигом вперёд для лучшей видимости).
* На карте отображаются:
  * **Пройденный путь** — зелёная линия.
  * **Оставшийся путь** — синяя линия.
  * Метки старта, финиша и текущее местоположение пользователя (с кастомной иконкой-стрелкой).
* В реальном времени рассчитываются:
  * **Оставшееся расстояние** до финиша (в км).
  * **ETA** — ориентировочное время прибытия на финиш (в минутах), исходя из средней скорости.
* Каждое обновление местоположения отправляется в **Firebase Realtime Database** по пути:
```
users/{userId}/location
```
с координатами и меткой времени.
* Маршрут продолжает обновляться и перестраиваться по мере движения, пока не будет достигнута конечная точка.
> 📌 При изменении bearing (азимута движения) маркер и камера синхронизируются, чтобы пользователь всегда видел направление вперёд.

### 👥 Работа с друзьями
Пользователи могут добавлять друг друга в друзья с помощью отправки запроса. Вся логика реализована на базе Cloud Firestore.

Данные хранятся в коллекциях:
- friend_requests — заявки в друзья.
- friends — список взаимных друзей.

При отправке запроса создаётся документ с from_user_id, to_user_id и статусом pending.

Пользователь, получивший заявку, может:
- Принять запрос — тогда создаются два документа в friends (в обоих направлениях), а заявка удаляется.
- Отклонить запрос — друг не добавляется, заявка удаляется.

Также реализованы действия:
- Удаление друга (удаляются оба связанных документа из коллекции friends).
- Отмена исходящего запроса.

Все действия синхронизированы с интерфейсом: список друзей, входящие и исходящие заявки обновляются в реальном времени.

🔐 Firestore Rules обеспечивают безопасность: только участники заявки могут читать, обновлять или удалять её. Также нельзя подделать user_id при создании связи.
